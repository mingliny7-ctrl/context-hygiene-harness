# 新增分析修复与打开时自动分析

起点 `ce77362`。本轮用户将原先手动分析要求改为：每次打开 Atlas 检查新增，有可信新增则自动分析；已完成内容复用。概念细分仍使用单独预算确认。

## 失败证据与修复

- 真实对话 `6afe6dc0-d7b8-83ec-af14-a5b18969a5d7` 最近三次旧请求均为 `INCOMPLETE_RESPONSE`。旧客户端把输出截断、过滤及不完整信封合为同一错误，且未保存 usage/结束原因，不能断言旧失败均由输出截断导致。
- 原批次发送八条消息，输入保守上界 69,810，输出限额 4,096。改为优先约24KB的完整讨论轮次窗口；单轮长回答可以超过此偏好值，仍按模型真实容量检查，不截断原文、不新增单轮硬限制。Prompt 要求精简结构化索引。
- 独立失败测试复现主题延续后累计结论超过10条被拒绝。Segment 的持久化结论与证据取消累计条数限制；单次模型输出仍最多10条。旧结论在本地保留，不重复发送；已有 Module 5 schema 不变。
- 请求失败后的按钮禁用未恢复已复现并修复。Provider 在不完整结果中保留安全 usage/请求号/结束原因，截断显示 `OUTPUT_TRUNCATED`；结构错误仅保存白名单字段名与类型，不记录原始输出正文。

## 自动执行契约

页面加载现有图谱后，单次 POST `/api/atlas/auto-index` 启动 Atlas 内部后台扫描；GET、服务启动、普通轮询不触发模型。只处理未隐藏、身份与顺序可信、具有完整问答的新增范围；历史补录/修改仍待复核。

所有对话共享一次打开的现有预算：默认最多2次模型请求、262,144输入保守额度、8,192输出额度、360秒。最近更新对话优先；达到预算保留成功批次，不自动无限续跑。未完成范围可用原按钮继续，或下次打开继续。源库只读，派生结果沿用原子提交与幂等覆盖。

同一进程多页面复用同一次打开任务；跨进程打开锁与原有执行锁避免同范围并发。最近自动任务60秒内的重复打开暂停，以免连续刷新消耗新预算。自动任务失败/结果不明的同范围不因刷新再次付费，保留手动重试入口。未回答的末尾 User 保持待采集。
